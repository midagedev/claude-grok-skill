# grok-delegate

**생각은 Claude 세션이, 타이핑은 grok 구독이.**

[English](./README.md) | [한국어](./README.ko.md)

로컬 **grok CLI**를 헤드리스 구현 서브에이전트로 부리는 Claude Code 스킬입니다. 리드 Claude 세션은 판단이 필요한 일(스펙·diff 리뷰·게이트·커밋)만 하고, 구현·기계적 수정·스크린샷 판정까지 grok에 위임합니다 — grok 구독이 있으면 그 토큰은 사실상 무료입니다.

단순 래퍼가 아니라 **운영 매뉴얼**입니다. 상위 구현 모델과의 9라운드 블라인드 비교 실험에서 증류했고, 스킬의 프롬프트 장치를 적용하자 grok의 자기 저작 테스트 깊이가 **단언 14개에서 81개로**, 0:5 블라인드 패배가 시각축 승리로 뒤집혔습니다 — 근거는 [아래](#정말-되나요)에.

## 설치

플러그인 마켓플레이스에서:

```
/plugin marketplace add midagedev/claude-grok-skill
/plugin install grok-delegate@claude-grok-skill
```

또는 설치 스크립트로 ([로컬 오버레이](#로컬-오버레이)를 쓸 거면 이쪽 권장):

```bash
git clone https://github.com/midagedev/claude-grok-skill
cd claude-grok-skill
./install.sh            # 사용자 스코프: ~/.claude/skills/grok-delegate/
./install.sh --project  # 프로젝트 스코프: ./.claude/skills/grok-delegate/
```

[Claude Code](https://claude.com/claude-code)와 로그인된 `grok` CLI(grok 구독)가 필요합니다.

## 사용

아무 Claude Code 세션에서 **"이거 grok으로 돌려줘"**라고 말하거나 `/grok-delegate`를 입력하면, Claude가:

1. 동봉된 프리앰블+템플릿으로 **자립적인 스펙**(파일 경로·수치 계약·검증 명령)을 쓰고,
2. 실측 검증된 플래그 조합(`--reasoning-effort xhigh --max-turns 1200 --always-approve` + git 안전 프로파일)으로 grok을 **백그라운드 헤드리스 투입**하고,
3. **리드답게 검수합니다**: diff를 직접 읽고, 게이트를 자기 소유로 재실행하고, grok 보고서가 실제로 새는 지점 8곳의 체크리스트를 돕니다.

| 역할 | 담당 |
|---|---|
| 오케스트레이션·스펙·diff 리뷰·게이트·커밋 | 리드 Claude 세션 |
| 구현·기계적 수정·수치 하네스 | `grok` CLI (헤드리스) |
| 스크린샷·시각 판정 | `grok` CLI — 평결이 계측과 어긋날 때만 Claude로 격상 |

핵심 원칙: **grok은 촘촘한 스펙의 실행자입니다.** 대화 컨텍스트가 없으므로 모든 위임은 그 자체로 완결돼야 하고, 취향 판단은 절대 묻지 않습니다 — 수치 계약만.

## 품질 번들

실제로 격차를 닫은 다섯 장치 — 각각 측정된 효과가 있습니다:

1. **계약↔단언 매핑 표** + FAIL-first 증거 — 이것 하나로 자기 저작 테스트 깊이 4배
2. **깊이의 정량화** — "꼼꼼히" 대신 "조항당 단언 2개 이상, 커버리지 표, 발견한 결함은 네 범위 안에서 방어까지"
3. **셀프 리뷰 패스** — "놓쳤을 결함 클래스 3개를 나열하고 각각 단언화하거나 사유 보고"
4. **시각 자기검증** — grok이 자기 캡처를 직접 열어 대조; 체크리스트 1번은 항상 *정체성 가독*("X로 읽히는가? 무엇으로 오독될 수 있는가?")
5. **로직 설계 원칙 4항** — derive-don't-store · 로드 시 재정규화 · 입력 3분류 방어 · 적대적 API 셀프 리뷰

## 정말 되나요?

같은 스펙을 grok과 상위 구현 모델에 병렬 워크트리로 주고, 9라운드를 블라인드(무기명, 라운드마다 라벨 스왑)로 판정했습니다. 요약:

- **기준선: 명백한 패배.** 블라인드 0:5; 상대가 단언 24개를 쓸 때 grok은 14개.
- **번들 적용 후: 중요한 곳에서 격차가 닫힘.** 단언 깊이 14 → 42 → 67 → **81**; 마지막 두 라운드에서 시각축이 grok 승으로 반전; 속도는 내내 2~4배.
- **끝까지 어려웠던 것:** 설계 무게가 있는 로직 코어(상태 기계·직렬화)는 번들 v3로도 패배 — 그래서 스킬은 그런 코어를 Claude가 쓰고 grok이 리뷰하라고 말합니다.
- **가장 유용한 발견:** grok의 블라인드 패배는 대부분 **능력 부족이 아니라 기본값의 부재**였고 — 기본값은 스펙에 써넣을 수 있습니다.

| E8 | FOV 큐 시스템 | v2, 상위 모델 상대 | 분할: 시각 승, 코드 패배 | 상대가 *리드의 스펙 결함*을 발견 |
| E9 | 타이밍 판정 상태 기계 | + 로직 설계 원칙 4항 (v3) | 패배; 리뷰어가 grok의 설계 선택을 명시 인정 | 단언 81; 최속 완주 (1,112초) |

E3의 교훈: grok은 체크리스트 6축 전부 SHIP을 자기 신고하고도 졌습니다 — 렌더가 *구름으로 읽히지 않아서*. 체크한 축은 전부 유효했고, 실패는 체크리스트 밖에 있었습니다. **정체성 가독**을 1번 필수 항목으로 만든 것이 E7·E8 시각 승리에 선행합니다.

수렴한 배정표 (우리의 실전 기본값):

| 과제 유형 | 배정 |
|---|---|
| 기계적 수정·FIX 반영·이식·튜닝 | **grok** — 무패 |
| 신규 시각 시스템 | **grok 1차** + 블라인드 비전 게이트; FIX 2회 초과 시 Claude 재저작 |
| 로직 코어 (상태 기계·직렬화) | Claude가 쓰고 grok이 리뷰 |
| 판정 (비전·코드 리뷰) | **grok** — 자기 구현을 여러 번 기각; 자기 편향 없음 |

## 구성

| 파일 | 역할 |
|---|---|
| `skills/grok-delegate/SKILL.md` | 호출 레시피, git 안전 프로파일, 품질 번들, 병렬 트랙 격리, 리드 검수 체크리스트 |
| `references/spec-preamble.md` | 모든 스펙 앞에 붙는 공통 규칙 — 전부 실제 사고에서 나온 조항 |
| `references/spec-template.md` | 과제별 스펙 골격: 계약·깊이 요구·시각 자기검증 |

안전 기본값: 위임은 열거식 git-deny 프로파일로 돕니다 — grok은 이력·PR을 읽을 수 있지만 커밋·푸시·상태 변경은 못 하고, 그건 리드 몫으로 남습니다. 세 프로파일(strict / 전면 차단 / 워크트리 한정 trusted)은 SKILL.md에 문서화돼 있습니다.

## 로컬 오버레이

프로젝트/개인 전용 컨텍스트(역할표·하우스 게이트 레시피·모델 배정표)는 설치된 스킬 옆 `references/local-overlay.md`에 — 자동으로 함께 적용되고, `install.sh`가 업그레이드에서 보존하며, 이 레포는 배포하지 않습니다.

## 알려진 한계

- 스펙을 쓸 수 없는 탐색적 문제는 위임 대상이 아닙니다 — 리드가 먼저 좁히세요.
- 설계 무게가 있는 로직은 번들 v3로도 완전히 닫히지 않았습니다; Claude가 쓰고 grok이 리뷰하세요.
- 참조 이미지는 과제와 같은 이펙트 유형일 때만 도움이 됩니다.
- grok 보고서는 대체로 정직합니다; 위험은 *없는 것*입니다 — 그래서 리드 검수 체크리스트가 있습니다.
- 지금은 Claude Code 전용입니다. SKILL.md 형식 자체는 이식 가능하지만, 끝까지 실증한 것만 공개합니다.
