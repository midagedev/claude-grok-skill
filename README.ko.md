# outsource

**생각은 Claude 세션이, 타이핑은 더 싼 모델 구독이.**

[English](./README.md) | [한국어](./README.ko.md)

**타사 모델 CLI들을 헤드리스 구현 서브에이전트로** 돌리는 Claude Code 스킬입니다. 리드 Claude 세션은 판단이 필요한 일(스펙, diff 리뷰, 게이트, 커밋)만 잡고, 구현·기계적 수정·조사·스크린샷 판정까지 구독 요금제에서 사실상 공짜인 모델 토큰으로 하청을 줍니다:

| 백엔드 | 구동 | 쓰는 자리 | 하드 제약 |
|---|---|---|---|
| **GLM-5.3** — 기본값 | z.ai 코딩플랜을 `bin/outsource-run.sh`가 **두 하네스** 중 하나로 구동 — 헤드리스 Claude Code(`claude -p`, 기본) 또는 `crush` CLI | 스펙으로 쓸 수 있는 모든 라운드: 구현, 게이트 저작, 코드 조사, 정직한 공개 | **이미지를 못 봄**; 스타일/UI 상호작용 저작은 실측 열세 |
| **grok-4.6** — 예외 | `grok` CLI | GLM이 구조적으로 못 하는 것: **비전 판정**, 이미지/비디오 생성, 웹 리서치 | 판정이 계측과 어긋나면 Claude로 에스컬레이션 |

래퍼가 아니라 **영수증이 붙은 운영 매뉴얼**입니다 — 백엔드별로 하나씩, 실측 실험 두 시리즈가 [아래](#실제로-되나)에 있습니다.

프로바이더 추가는 코드 분기가 아니라 **테이블 한 줄**입니다 — base URL, 크레덴셜 출처, 기본 모델, 비전 가능 여부.

## 설치

플러그인 마켓플레이스:

```
/plugin marketplace add midagedev/outsource
/plugin install outsource@outsource
```

또는 설치 스크립트([로컬 오버레이](#로컬-오버레이)를 쓸 거면 이쪽):

```bash
git clone https://github.com/midagedev/outsource
cd outsource
./install.sh            # 사용자 스코프: ~/.claude/skills/outsource/
./install.sh --project  # 프로젝트 스코프: ./.claude/skills/outsource/
```

[Claude Code](https://claude.com/claude-code)와 백엔드 최소 하나가 필요합니다 — 인증된 `grok` CLI, 그리고/또는 `crush` 설정에 들어 있는 z.ai 코딩플랜 키(런처가 키를 거기서 읽고 기본은 헤드리스 Claude Code로 돌립니다 — `crush` CLI 자체는 `--harness crush`일 때만 필요). 크레덴셜은 발사 시점에 읽어 curl의 stdin이나 프로세스 환경으로만 넘어갑니다 — 이 스킬이 만드는 파일에는 키가 들어가지 않습니다.

## 업데이트

마켓플레이스: `/plugin marketplace update outsource` 후 `claude plugin update outsource`. 스크립트 설치: `git pull && ./install.sh` — 체크섬 매니페스트 덕에 무수정 설치본은 플래그 없이 업그레이드되고, 손으로 고친 설치본만 `--force`가 필요합니다(`references/local-overlay.md`는 항상 보존).

## 사용

아무 Claude Code 세션에서 **"grok으로 돌려"** 또는 **"glm/crush로 돌려"** 라고 말하거나 `/outsource`를 호출하면, Claude가:

1. 번들된 preamble + 템플릿으로 **자기완결 스펙**(파일 경로, 수치 계약, 검증 명령)을 쓰고 (`references/spec-authoring.md`의 품질 번들이 실측으로 품질 격차를 닫은 장치들입니다),
2. 돈을 쓰기 전에 **스펙을 린트하고 플랜 쿼터를 확인**하고 ([아래](#가드레일-라운드-전과-후)),
3. 백엔드를 **백그라운드 헤드리스**로 실전 검증된 레시피(`references/grok.md` / `references/glm.md`)대로 발사하고,
4. **리드답게 검수합니다**: diff를 직접 읽고, 게이트를 콜드로 재실행하고, 위임 보고서가 실제로 새는 지점 11개 체크리스트를 돕니다.

핵심 원칙: **위임받는 쪽은 촘촘한 스펙의 실행자입니다.** 대화 컨텍스트가 없으니 모든 위임은 홀로 서야 하고, 취향 판단은 절대 시키지 않습니다 — 수치 계약만.

## 가드레일: 라운드 전과 후

위임 라운드는 사람이 하는 라운드와 다른 방식으로 실패합니다 — 스펙이 옮겨진 파일을 인용하거나, 플랜 크레딧이 중간에 떨어지거나, 엔드포인트가 조용히 다른 모델로 답하거나. 이제 각각이 조언 문단이 아니라 **종료 코드가 붙은 검사**입니다.

**발사 전**

```bash
bin/spec-lint.sh --root <repo> <scratch>/spec.md     # 0 깨끗 · 1 발견
bin/outsource-run.sh --require-quota 15 …            # 플랜이 부족하면 66
```

- **`spec-lint.sh`** — 스펙의 모든 `path:line` 인용과 경로꼴 참조를 해석해서, 존재하지 않는 경로나 파일 끝을 넘는 줄 번호에서 실패합니다. 실측된 한 세션에서 잘못된 전제 다섯 개(없는 툴, 없는 컬럼, 없는 픽스처, 틀린 실행 디렉터리, 틀린 매니페스트 경로)가 각각 라운드의 일부를 태웠습니다 — 위임받은 쪽이 잡긴 하지만, 이미 시작한 뒤입니다. 그럴듯한 베이스 어디에서든 해석되는 참조는 잡지 않고, 템플릿(`<placeholder>`, `$VAR`, glob, URL)도 잡지 않습니다. **무시당하는 린터는 없느니만 못하니까요.**
- **`--require-quota N`** — 플랜이 끝낼 수 없는 라운드를 아예 시작하지 않습니다. 기준은 **가장 짧은 창이 아니라 가장 빡빡한 창**입니다(실측: 주간 창이 81.7% 남았을 때 5시간 창은 83.8%였습니다 — 짧은 쪽이 구속 조건이 아닙니다). 그리고 **닫히는 쪽으로 실패**합니다 — 평가할 수 없는 게이트는 통과한 게이트가 아닙니다.
- **비전 가드** — 스펙이 이미지 파일을 참조하는데 프로바이더 테이블 행이 "이미지를 못 봄"이면 거부합니다(exit 65). 능력 판단은 테이블에서 오지, 호출 지점의 프로바이더 이름 비교에서 오지 않습니다.
- **git 가드** — 실제 명령 문자열을 파싱하는 `PreToolUse` 훅입니다. `git -C … commit`, `env … git push`, `sudo git …`, 체인된 변경까지 모두 차단하고 읽기 전용 git은 의도적으로 열어 둡니다. 두 훅 규약을 모두 말하므로 crush와 Claude Code 하네스를 파일 하나가 지킵니다.

**라운드 후**

- **모델 정체성 단언**(exit 70). z.ai는 모델을 안 박은 `claude-*` 요청을 플랜 기본값으로 조용히 매핑하므로, 요청하지 않은 모델로 라운드가 돌 수 있습니다. 런처는 세션 트랜스크립트의 턴별 `message.model`에서 실제로 답한 모델을 읽습니다 — `modelUsage`가 **아닙니다**. 그건 실측 결과 **요청한 id를 되비추기만** 해서 일치를 증명할 수 없습니다. 트랜스크립트가 없으면 "검증 불가"이고, 그것도 실패입니다.
- **완료 센티넬** `<log>.rc` — `rc`, `finished`, `harness`, `provider`, `model_requested`, `model_actual`, `session`. 하네스의 수명 신호는 완료 증거가 아닙니다. 이 파일이 증거입니다.
- **비용 한 줄** — 로그 `usage`의 토큰 수입니다. 라운드에 귀속되는 유일한 숫자라 그것만 인용할 값어치가 있습니다. 옆의 `total_cost_usd`는 Anthropic 단가 추정이고 여기 있는 어느 프로바이더에도 맞지 않습니다.

플랜 크레딧은 **의도적으로 라운드별로 보고하지 않습니다.** 플랜 쿼터는 동시에 도는 다른 라운드와 다른 세션까지 함께 움직이는 플랜 전역 카운터라, 한 라운드 전후 차이는 라운드가 아니라 그 시각의 머신을 잰 값입니다(실측: 여섯 라운드를 동시에 돌리면 각각의 델타가 전부 상한값이 됩니다). 쿼터는 **발사 전** 신호입니다 — 이 세션이 어느 프로바이더를 쓸지, 그리고 시작해도 되는지.

`bin/quota.sh`가 그걸 읽습니다 — 구독형 백엔드 둘 다:

```
$ quota.sh
z.ai coding plan: level max — GLM Coding Max (status VALID, valid 2026-08-15~09-15)
5h window: 6692/28000 consumed, 21307 remaining, 23% used / 76.1% left, resets at 12:24 (in 3h 46m)  <- tightest
1w window: 27758/140000 consumed, 112241 remaining, 19% used / 80.2% left, resets at 17:52 (in 153h 14m)

$ quota.sh --provider grok
1w window: exact counts not exposed by this API, 98.0% used / 2.0% left, resets at 15:13 (in 6h 36m)
```

## 품질 번들

품질 격차를 실제로 닫은 장치들, 각각 실측 효과와 함께:

1. **계약↔단언 매핑 표** + FAIL-first 증거 — 이것만으로 자가 저작 테스트 깊이 4배
2. **정량화된 깊이** — "꼼꼼히"가 아니라 "계약 조항당 단언 ≥2, 커버리지 표, 발견한 결함은 스코프 안에서 방어"
3. **자기 리뷰 패스** — "놓쳤을 결함 클래스 3개를 대고, 단언하거나 사유를 써라"
4. **시각 자기검증** — 구현자가 자기 캡처를 직접 열람; 체크리스트 1번은 언제나 *정체성 가독*("이게 X로 읽히나? 뭘로 오독될 수 있나?")
5. **로직 설계 원칙** — derive-don't-store · 로드 시 재정규화 · 3분류 입력 방어 · 적대적 API 자기검토
6. **증거 규칙** (GLM 라운드 이후 추가) — 콜드 스타트로 검증하고 테스트 개수를 CI와 대조; 모든 수치엔 그걸 만든 명령을 첨부; 재발 방지 층은 문장이 아니라 파일로; 아티팩트/코드 발산엔 탐지기

## 실제로 되나?

백엔드별로 한 시리즈씩, 두 번 측정했습니다. 방법은 같습니다: **같은 스펙**을 하청 백엔드와 프런티어 Claude 모델에 병렬 git 워크트리로 주고, 실제 프로덕션 작업에서, 블라인드 판정 또는 리드의 라인 단위 검수로 비교.

### grok-4.6 — Opus 5 / Fable 5 상대 블라인드 9라운드

라운드마다: Three.js/WebGPU 프로젝트에서 모듈을 구현하고 *자기 검증 게이트까지 저작*. 산출물은 **블라인드** 판정(무표기 소스, 매 라운드 라벨 교체).

- **베이스라인: 완패.** 블라인드 0:5; grok 단언 14개 vs Opus 5 24개.
- **번들 적용 후: 중요한 곳에서 격차가 닫힘.** 단언 깊이 14 → 42 → 67 → **81**; 마지막 두 라운드에서 시각 축이 grok 승으로 뒤집힘(Opus 5 상대 1회, Fable 5 상대 1회); 속도는 내내 2~4배.
- **끝까지 어려웠던 것:** 설계 하중이 큰 로직 코어(상태 기계, 직렬화)는 세 번 모두 Claude 쪽.
- **가장 중요한 발견:** grok의 블라인드 패배는 대부분 **능력 부재가 아니라 디폴트 부재** — 그리고 디폴트는 스펙에 적어 넣을 수 있다.

### GLM-5.3 — 단독 3라운드 출하, 그리고 Opus 서브에이전트와 동일 스펙 A/B

다른 레포(Go + Svelte 제품, 게이트 CI), 다른 방법: 블라인드 패널 없이 리드가 모든 diff를 라인 단위로 읽고 모든 게이트를 콜드로 재실행.

- **단독 3라운드 전부 출하**: CLI/MCP 경고 기능, FAIL-first 테스트가 붙은 스토어 스키마-발산 복구, 문서 계약 CI 게이트 — 셋 다 리드 검수 후 재작업 없이 main 안착. 그 과정에서 GLM은 리드가 쓴 스펙의 잘못된 전제 5개(존재하지 않는 도구, 없는 컬럼, 틀린 작업 디렉토리 등)를 잡아 정정했습니다.
- **동일 스펙 A/B (N=3: 웹 UI 터치 버그, 자기검증 약속 문서, 생태계 셸 스크립트).** 놀라웠던 대등함: 두 팔이 같은 공용 팝오버 유틸을 독립 선택, 단위 하네스가 컴포넌트를 마운트 못 하자 **같은 AST 기반 테스트 우회를 독립 발명**, 같은 스펙 전제 오류를 포착, FAIL-first 증거를 시키지 않아도 생산.
- **아티팩트 채택은 Opus 팔 3:0** — 격차는 셋 다 서술 가능했고, 셋 다 이 스킬의 스펙 규칙이 됐습니다:
  1. **2차 상태 상호작용.** GLM은 팝오버 둘이 같은 슬롯을 동시 점유하고 Escape가 두 일을 하는 상태를 남김; Opus는 슬롯과 키 순서를 중재. → UI 스펙은 같은 공간·키를 쓰는 요소를 열거하고 우선순위 결정을 요구할 것.
  2. **증거 강도.** GLM은 집중 `go test -run`이 있는 자리에서 grep+산문 주석으로 증명; Opus는 테스트를 실행하고, 명령이 증명 못 하는 문장 2개를 좁히고, 증명 불가 약속 1개는 의도적으로 뺌. → grep보다 기존 테스트 호출; 명령 블록 안 주석이 주장을 대신하면 안 됨.
  3. **침묵 회피.** GLM의 `sh`/`set -eu` 선택은 SIGPIPE 실패 모드를 우연히 피했고 언급이 없었음; Opus는 그걸 실측(pipefail 아래 비결정 exit 141)하고 설계로 닫음 — 리뷰에서 운과 판단은 구분 불가. → 견고성 스크립트는 선택한 옵션이 막는 실패 모드를 명명할 것.
- 그 라운드들 안에서 GLM의 자체 승점도 있었습니다: Opus 팔이 놓친 문서화된 env 변수를 발굴해 **스크립트 무수정 엔드투엔드 스모크**를 해냈고, FAIL-first 증명을 **양방향**(추가와 삭제)으로 돌렸습니다.

### 3-way 라운드: Opus 5 대 grok-4.6 대 GLM-5.3, 실제 티켓 5개에 14라운드

세 번째 시리즈이자 이 스킬을 가장 많이 바꾼 실험입니다. Go + Svelte 제품의 열린 티켓 5개(동기화 성능 버그, CLI 업그레이드 버그, 새 CLI 동사, 인증 온보딩 버그, UI 정렬 버그)를 각 팔에 **같은 태스크 스펙**으로, 각자의 git 워크트리에 보냈습니다. 총 14라운드. 리드가 직접 재실행한 `build`·`vet`·해당 스위트를 **14개 전부** 통과했습니다.

전부 통과했으니, 흥미로운 차이는 게이트 바깥에 있습니다.

**팔들이 일치한 곳.** 명시된 사실이 그냥 틀렸을 때는 모두가 잡습니다. 동기화 버그 스펙에는 제보자의 가설("무변경 틱에서는 워터마크 창이 좁혀지지 않는다")과 함께 한 줄이 들어 있었습니다 — *이 진단을 믿지 마라. 개입 실험으로 확정하거나 기각하라.* Opus는 창의 여유분을 없앴고(`overlap 5분 → 0`) 증상이 그대로였습니다. grok은 워터마크를 모든 페이지보다 한 시간 뒤로 밀어 매치를 0으로 만들었고 fetch가 0이었습니다. **반대 방향의 조작, 같은 기각.** 원인은 워터마크가 아니라 검색 히트와 본문 요청 사이에 **판단이 없었다**는 것이었고, 두 팔 모두 상수를 튜닝하는 대신 "이 페이지의 본문을 받아야 하는가"의 단일 소유자를 만드는 같은 모양의 수정을 냈습니다.

**갈린 곳: 만족시킬 수 없는 계약.** 업그레이드 버그 스펙은 동시에 성립할 수 없는 두 가지를 요구했습니다 — `name: gadak`을 가진 파일은 우리 것이니 덮어써라, 그리고 사용자가 저작한 파일은 계속 보호해라. 우리 스킬을 커스터마이즈한 사용자도 그 줄은 남깁니다. 그게 있어야 스킬로 로드되니까요. grok은 **알아챘고 적어놓기까지 했습니다**(*"본문을 수정했지만 `name: gadak`을 남긴 사용자는 우리 것으로 취급되어 덮어써진다"*) — 그리고 스펙대로 구현했습니다. GLM 두 팔은 알아채지도 못했습니다. Opus만 규칙을 거부하고 두 조항이 왜 동시에 성립 불가인지 논증한 뒤 우회 설계를 냈습니다(내용 해시 영수증 + 영수증 이전 설치본을 위한 **의도적으로 동결된** 다이제스트 표, 그리고 그 표가 동결로 남는지 단언하는 테스트).

인증 티켓에서 같은 모양이 반복됐습니다. 계약이 세 실패 사례를 구별하라고 했는데 가용한 증거로는 구별이 불가능한 상황이었고, 세 팔 모두 그 결론에 도달했습니다. Opus는 구별 가능한 하나만 실제로 분류하고 나머지를 부분 미달로 신고한 뒤 메시지에 자가 확인법을 심었습니다. GLM 팔들은 모든 힌트를 모든 에러에 이어붙였습니다 — "사용자에게 문자열을 보여라"의 문자는 지키면서 계약의 요점은 조용히 놓친 겁니다.

정리하면 **틀린 사실은 모두가 잡고, 불가능한 요구는 하나만 잡습니다.** 실패 형태가 빨간 게이트가 아니라 **이름 없는 구멍이 있는 초록 게이트**라는 점이 문제입니다. 리드는 diff를 읽지만, 언급되지 않은 누락은 볼 수 없으니까요.

이 시리즈에서 나온 스펙 결함 4개 중 3개는 **리드 자신의 것**이었고 위임받은 쪽이 찾았습니다. 그중 하나는 부정 주장("이 파일은 존재하지 않는다")이었는데, 원인은 zsh에서 패턴 두 개를 준 `ls`였습니다 — 두 번째 glob이 매치에 실패해 명령 전체가 중단되고 아무것도 출력되지 않아서, 존재하는 파일이 없는 것으로 스펙에 들어갔습니다. 이건 이제 `tail` 함정 옆에 리드 체크리스트 항목으로 있습니다.

### preamble은 그 길이값을 하는가 (같은 티켓 5개, GLM-5.3, 전체 대 없음)

시리즈 안에서 돌린 통제 A/B입니다. 같은 태스크 스펙, 같은 모델, 같은 하네스, 공유 preamble만 붙이거나 통째로 뺐습니다.

| 티켓 | 출력 토큰, 없음 ÷ 전체 | 입력 토큰, 전체 → 없음 |
|---|---|---|
| 새 CLI 동사 | 0.63× | 298k → 139k |
| 동기화 성능 | 0.78× | 146k → 112k |
| UI 정렬 | 0.84× | 107k → 95k |
| 인증 온보딩 | 0.86× | 166k → 96k |
| CLI 업그레이드 | 0.94× | 81k → 78k |

다섯 전부 더 쌌고, 넷에서 턴이 적었고, **게이트가 나빠진 적은 한 번도 없습니다.** 동기화 버그에서는 preamble 없는 팔이 grok이 놓친 2차 함정(새 게이트에 걸러진 페이지도 comments-only 패스가 도달할 수 있어야 함)을 잡고 회귀 테스트까지 썼습니다.

그런데 preamble이 값을 하던 자리는 비용 쪽이 아니었습니다:

| | preamble 전체 | preamble 없음 |
|---|---|---|
| FAIL-first 증거 | 5/5 | **5/5** |
| 자기검증 절 | 5/5 | **0/5** |
| "못 한 것" 공개 | 5/5 | **1/5** |

FAIL-first는 preamble 없이도 살아남습니다. **태스크 스펙**이 요구하니까요. 사라지는 건 공개(disclosure)이고, 인증 라운드가 완성된 것처럼 돌아온 경로가 정확히 그것입니다. 즉 preamble이 사던 것은 더 나은 코드가 아니라 **정직한 보고**였습니다.

그래서 `references/spec-preamble-core.md`를 만들었습니다 — 사라진 그 부분만 정확히 되가져오고 그 외에는 아무것도 넣지 않은 짧은 파일입니다. 공유 코드를 건드리거나 계약이 만족 가능한지 확신이 없는 라운드에는 전체 preamble을 그대로 씁니다.

이 실험이 **확정하지 못한 것 두 가지**: 전체 preamble의 어느 절이 사문인지(전부 대 전무만 측정했습니다), 그리고 라운드별 플랜 크레딧 비용(플랜 쿼터는 동시에 도는 라운드도 함께 움직이는 플랜 전역 카운터라, 그 숫자들은 해석 불가로 폐기했습니다).

**두 시리즈를 관통하는 정직한 요약:** 싼 백엔드는 **스펙이 계약을 다 써주면** 신뢰할 수 있는 구현 팔이고, 패배는 스펙이 비워 둔 판단에서 납니다. 이 레포의 대부분이 스펙 저작 자료인 이유입니다.

정착한 배정표 (우리 프로덕션 기준):

| 과제 유형 | 배정 |
|---|---|
| 기계적 수정, FIX 라운드, 포팅, 튜닝, 게이트 저작, 조사 | **하청 백엔드** |
| 신규 시각 시스템 | 하청 1차 + 블라인드 비전 게이트; FIX 2회 실패 시 Claude 재저작 |
| 스타일 / 룩 / UI 상호작용 저작 | Claude (A/B 실측) |
| 로직 코어 (상태 기계, 직렬화) | Claude가 먼저, 백엔드가 리뷰 |
| 판정 (비전, 코드 리뷰) | grok — 자기 구현물도 여러 번 기각; 자기 편향 미관측 |

## 알려진 한계

- 스펙으로 못 쓰는 탐색형 문제는 위임 대상이 아닙니다 — 리드가 먼저 좁힙니다.
- 설계 하중이 큰 로직은 번들 v3로도 완전히 닫히지 않았습니다; Claude로 쓰고 백엔드로 리뷰하세요.
- GLM-5.3은 이미지를 못 봅니다, 예외 없이 — 그리고 (실측) 추측하는 대신 못 본다고 말합니다.
- z.ai의 Anthropic 호환 엔드포인트는 모델명을 안 박으면 플랜 기본값(실측: glm-4.7)으로 조용히 매핑합니다. 런처가 모델을 고정하고 무엇이 답했는지 단언하지만, 그 단언에는 세션 트랜스크립트가 필요합니다 — 로그의 `modelUsage`는 *요청한* id를 되비출 뿐 아무것도 증명하지 못합니다.
- 플랜 쿼터는 **구독형 백엔드 둘**에서만 읽힙니다. Claude와 종량제 API 키는 확인할 창 자체가 없어서 게이트할 대상이 없습니다.
- grok은 퍼센트만 노출하고 크레딧 개수를 주지 않으므로, grok 라운드의 값은 크레딧 수가 아니라 퍼센트 차이입니다.
- 보고서는 양쪽 다 대체로 정직합니다; 위험은 *말하지 않는 것*에 있습니다 — 리드 검수 체크리스트가 있는 이유.
- 아직 Claude Code 전용입니다. SKILL.md 형식은 이식 가능하지만, 끝까지 검증한 것만 공개합니다.
