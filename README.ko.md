# grok-delegate

**생각은 Claude 세션이, 타이핑은 grok 구독이.**

[English](./README.md) | [한국어](./README.ko.md)

로컬 **grok CLI**를 헤드리스 구현 서브에이전트로 부리는 Claude Code 스킬입니다. 리드 Claude 세션은 판단이 필요한 일(스펙 작성·diff 리뷰·게이트·커밋)만 하고, 코드 구현·기계적 수정·스크린샷 판정까지 grok에 위임합니다 — grok 구독이 있으면 구현 토큰이 사실상 무료입니다.

이 스킬의 내용은 전부 실측입니다. 같은 스펙을 grok과 상위 구현 모델(Claude Opus / Fable)에 병렬 워크트리로 동시에 주고, 산출물을 **블라인드**(무기명, 라운드마다 라벨 스왑)로 판정하는 실험을 9회 돌렸습니다. 이 스킬은 그 시리즈에서 실제로 품질 격차를 닫은 장치들의 증류물입니다.

## 증거: 프롬프트 장치가 격차를 닫아온 궤적

시리즈의 가장 유용한 발견: **격차의 대부분은 모델 능력이 아니라 기본값의 부재였고**, 기본값은 스펙에 써넣을 수 있습니다.

| 실험 | 과제 | grok 스펙에 추가한 장치 | 블라인드 평결 | 측정 효과 |
|---|---|---|---|---|
| E1 | VFX 모듈 (에너지 배리어) | — (기준선) | 0:5 패배 | 자기 저작 테스트 단언 **14** vs 24 |
| E2 | VFX (격추 버스트) | — (재현) | 패배 | 단언 **12** vs 32; grok이 1.5배 빠름 |
| E3 | VFX (구름 파랄락스) | 공정화 + *자기 시각검증* | 패배 — 산출물이 그 사물로 안 읽힘 | 패인이 모델이 아니라 체크리스트에 있음을 발견 (아래) |
| E5 | 노출 플래시+히트스톱 | + `--rules` 프리앰블 주입, **계약↔단언 매핑 표** (번들 v1) | **2:0:1 승** (grok끼리 A/B) | 매핑 표 하나로 단언 **10 → 42** |
| E6 | 그레이즈 스파크 | 참조 이미지 주입 | **4:0:1 기각** | 참조는 *같은 이펙트 유형*일 때만 유효 — 다르면 형태 언어가 오염됨 |
| E7 | 불릿타임 시스템 | + 깊이의 정량화, 셀프 리뷰 패스, max-turns 1200 (번들 v2) | **분할: 시각축 승** (시리즈 첫 시각 승리), 로직축 패배 | 단언 **67** vs 95 — 격차 3배+ → 1.4배; 벽시계 2.2배 빠름 |
| E8 | FOV 큐 시스템 (상위 모델 상대) | 번들 v2 | 분할: 시각 승, 코드 패배 | 상대가 *리드의 스펙 결함*을 발견; 양쪽 합성 채택 |
| E9 | 타이밍 판정 상태 기계 | + 로직 설계 원칙 4항 (번들 v3) | 패배, 단 리뷰어가 grok의 단일 시간축 설계를 명시 인정 | 단언 **81**, 시리즈 최속 완주 (1,112초) |

시리즈 전체의 단언 깊이 궤적: **14 → 12 → 10 → 42 → 67 → 81**. 파인튜닝이 아니라 프롬프트 장치의 결과입니다.

E3의 교훈은 따로 적을 가치가 있습니다. grok은 체크리스트 6축 전부에 SHIP을 자기 신고했지만, 렌더가 *구름으로 읽히지 않아* 블라인드에서 졌습니다. 체크한 축은 전부 유효했고 — 실패는 체크리스트 밖에 있었습니다. **정체성 가독**("X로 읽히는가? 무엇으로 오독될 수 있는가?")을 체크리스트 1번 필수 항목으로 만든 뒤부터 grok의 자기 판정이 독립 블라인드 평결과 일치하기 시작했고, 이후 시각축 2연승(E7·E8)으로 이어졌습니다.

시리즈가 수렴한 곳 (우리의 실전 배정표):

| 과제 유형 | 배정 |
|---|---|
| 기계적 수정·FIX 반영·이식·튜닝·합성 라운드 | **grok** — 전 시리즈 무패 |
| 신규 시각 시스템 | **grok 1차**(번들 v2) + 블라인드 비전 게이트; FIX 2회 초과 시 Claude 재저작 |
| 로직 코어 (상태 기계·직렬화) | 상위 모델 우선, 또는 grok 초안 + Claude 리뷰 — 설계 무게 과제는 Claude 계열 3전 3승 |
| 판정 (비전·코드 리뷰) | **grok** — 자기 편향 없음 실증 (자기 구현을 여러 번 기각) |

## 동작 방식

| 역할 | 담당 |
|---|---|
| 오케스트레이션·스펙 작성·diff 리뷰·게이트·커밋 | 리드 Claude 세션 |
| 코드 구현·기계적 수정·수치 하네스 | `grok` CLI (헤드리스) |
| 스크린샷·시각 판정 | `grok` CLI (평결이 계측과 어긋날 때만 Claude로 격상) |

핵심 원칙: **grok은 촘촘한 스펙의 실행자입니다.** 대화 컨텍스트가 없으므로 모든 위임은 자립적인 스펙 파일 — 파일 경로·수치 계약·완료 조건·검증 명령 — 이어야 하고, 공유 프리앰블 + 과제별 섹션으로 조립해 백그라운드 헤드리스로 투입합니다.

## 설치

### Claude Code 플러그인 마켓플레이스

```
/plugin marketplace add midagedev/claude-grok-skill
/plugin install grok-delegate@claude-grok-skill
```

### 또는 설치 스크립트

```bash
git clone https://github.com/midagedev/claude-grok-skill
cd claude-grok-skill
./install.sh            # 사용자 스코프: ~/.claude/skills/grok-delegate/
./install.sh --project  # 프로젝트 스코프: ./.claude/skills/grok-delegate/
```

[로컬 오버레이](#로컬-오버레이)를 쓸 계획이면 스크립트 설치를 권합니다 — 업그레이드 시 오버레이를 보존합니다.

### 전제 조건

- [Claude Code](https://claude.com/claude-code)
- `grok` CLI 설치 + 로그인 (grok 구독)

설치 후 아무 Claude Code 세션에서 "이거 grok으로 돌려줘"라고 말하거나 `/grok-delegate`를 입력하면 됩니다.

## 구성

| 파일 | 역할 |
|---|---|
| `skills/grok-delegate/SKILL.md` | 스킬 본문: 호출 레시피(검증된 플래그 조합), git 정책 프로파일, 품질 번들, 병렬 트랙 격리, 리드 검수 체크리스트 |
| `skills/grok-delegate/references/spec-preamble.md` | 모든 위임 스펙 앞에 붙이는 공통 규칙 — 전부 실제 사고에서 나온 조항 |
| `skills/grok-delegate/references/spec-template.md` | 과제별 스펙 골격: 계약·깊이 요구·시각 자기검증 프로토콜 |

## 품질 번들 (요약)

다섯 장치 — 각각 위 표에 측정 효과가 있습니다:

1. **계약↔단언 매핑 표** + FAIL-first 증거 — 이것 하나로 자기 저작 게이트 깊이 4배
2. **깊이의 정량화** — "꼼꼼히" 대신 "조항당 단언 2개 이상, 커버리지 표, 발견한 결함은 네 범위 안에서 방어까지"
3. **셀프 리뷰 패스** — "놓쳤을 결함 클래스 3개를 나열하고 각각 단언화하거나 사유 보고"
4. **시각 자기검증** — grok이 자기 캡처를 직접 열어 대조; 체크리스트 1번은 항상 정체성 가독
5. **로직 설계 원칙 4항** — derive-don't-store · 로드 시 재정규화 · 입력 3분류 방어 · 적대적 API 셀프 리뷰

표준 플래그: `--reasoning-effort xhigh --max-turns 1200 --always-approve` + git 정책 프로파일.

## Git 정책 프로파일

`--deny 'Bash(git *)'` 전면 차단은 *읽기*까지 막습니다 — grok이 커밋 이력·blame·PR을 못 봅니다. 위임마다 선택하세요:

1. **strict (기본)** — 상태 변경 서브커맨드만 열거 차단; `git log/show/diff/blame`, `gh pr list/view`는 동작. 실측: 읽기 통과, `git commit` 차단, HEAD 불변.
2. **readonly-plus** — 전면 차단. 파일 경계가 민감한 병렬 트랙용.
3. **trusted** — deny 없음, **격리 워크트리 한정**. grok이 라운드 경계마다 WIP 커밋을 하길 원할 때. push/merge는 여전히 리드 몫.

glob deny는 안전망이지 증명이 아닙니다(`git -C <path> commit` 류 우회 가능) — 프리앰블의 git 규칙이 2차 방어선입니다.

## 로컬 오버레이

공유 스킬에 넣을 수 없는 프로젝트/개인 전용 컨텍스트(역할표·하우스 게이트 레시피·모델 배정표·함정 문서 목록)는 설치된 스킬 옆 `references/local-overlay.md`에 둡니다. 스킬이 자동으로 함께 적용하고, `install.sh`가 업그레이드 시 보존합니다. 이 레포는 오버레이를 배포하지 않습니다 — 플러그인 마켓플레이스로 설치했다면 관리형 플러그인 디렉터리는 업데이트 시 통째로 교체될 수 있으니, 오버레이 원본은 다른 곳에 두고 업데이트 후 다시 복사하세요.

## 알려진 한계 (정직하게)

- 스펙을 쓸 수 없는 탐색적 문제(멀티턴 원인 축소)는 위임 대상이 아닙니다 — 리드가 먼저 좁히세요.
- 미묘한 상태 기계 설계는 번들 v3로도 완전히 닫히지 않았습니다: 원칙 지시는 패인을 더 깊은 층(라이브/복원 이중 경로, 수선 vs 거절 경계)으로 옮겼을 뿐입니다. 설계 무게가 있는 코어는 Claude가 쓰고 grok이 리뷰하는 편이 안전합니다.
- 참조 이미지는 과제와 같은 이펙트 유형일 때만 도움이 됩니다 (E6이 정확히 이 이유로 4:0:1 기각).
- grok 보고서는 대체로 정직합니다; 위험은 보고에 *없는 것*입니다 — SKILL.md의 리드 검수 체크리스트 8항을 따르세요.
- 이 레포는 Claude Code 지원만 배포합니다. SKILL.md 형식 자체는 다른 에이전트로 이식 가능하지만, 우리는 끝까지 실증한 것만 공개합니다.
