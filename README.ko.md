# grok-delegate

**생각은 Claude 세션이, 타이핑은 grok 구독이.**

[English](./README.md) | [한국어](./README.ko.md)

로컬 **grok CLI**를 헤드리스 구현 서브에이전트로 부리는 Claude Code 스킬입니다. 리드 Claude 세션은 판단이 필요한 일(스펙·diff 리뷰·게이트·커밋)만 하고, 구현·기계적 수정·스크린샷 판정까지 grok에 위임합니다 — grok 구독이 있으면 그 토큰은 사실상 무료입니다.

단순 래퍼가 아니라 **운영 매뉴얼**입니다. 상위 구현 모델과의 9라운드 블라인드 비교 실험에서 증류했고, 스킬의 프롬프트 장치를 적용하자 grok의 자기 저작 테스트 깊이가 **단언 14개에서 81개로**, 0:5 블라인드 패배가 시각축 승리로 뒤집혔습니다 — 근거는 [아래](#정말-되나요)에.

## 설치

플러그인 마켓플레이스에서:

```
/plugin marketplace add midagedev/claude-grok-skill
/plugin install grok-delegate@claude-grok-skill
```

또는 설치 스크립트로 ([로컬 오버레이](#로컬-오버레이)를 쓸 거면 이쪽 권장):

```bash
git clone https://github.com/midagedev/claude-grok-skill
cd claude-grok-skill
./install.sh            # 사용자 스코프: ~/.claude/skills/grok-delegate/
./install.sh --project  # 프로젝트 스코프: ./.claude/skills/grok-delegate/
```

[Claude Code](https://claude.com/claude-code)와 로그인된 `grok` CLI(grok 구독)가 필요합니다.

## 업데이트

마켓플레이스로 설치했다면:

```
/plugin marketplace update claude-grok-skill
claude plugin update grok-delegate
```

스크립트로 설치했다면:

```bash
git pull && ./install.sh
```

`install.sh`는 설치 시점에 체크섬 매니페스트를 기록하므로, 손대지 않은 설치본의 업그레이드는 플래그 없이 통과합니다. 직전 설치 이후 설치본을 직접 수정한 경우에만 거부하며, 그때는 `--force`로 수정분을 버리고 덮어씁니다(`references/local-overlay.md`는 어느 경우든 보존). 매니페스트 도입 전에 설치한 사본은 최초 1회만 `--force`가 필요할 수 있습니다.

## 사용

아무 Claude Code 세션에서 **"이거 grok으로 돌려줘"**라고 말하거나 `/grok-delegate`를 입력하면, Claude가:

1. 동봉된 프리앰블+템플릿으로 **자립적인 스펙**(파일 경로·수치 계약·검증 명령)을 쓰고,
2. 실측 검증된 플래그 조합(`--output-format streaming-json --reasoning-effort xhigh --max-turns 1200 --always-approve` + git 안전 프로파일)으로 grok을 **백그라운드 헤드리스 투입**하고,
3. **리드답게 검수합니다**: diff를 직접 읽고, 게이트를 자기 소유로 재실행하고, grok 보고서가 실제로 새는 지점 8곳의 체크리스트를 돕니다. 라운드 중간에는 `scripts/grok-progress.py`로 NDJSON 로그를 도구 호출 한 줄씩 압축해 봅니다. `--output-format plain`도 그대로 동작합니다.

| 역할 | 담당 |
|---|---|
| 오케스트레이션·스펙·diff 리뷰·게이트·커밋 | 리드 Claude 세션 |
| 구현·기계적 수정·수치 하네스 | `grok` CLI (헤드리스) |
| 스크린샷·시각 판정 | `grok` CLI — 평결이 계측과 어긋날 때만 Claude로 격상 |

핵심 원칙: **grok은 촘촘한 스펙의 실행자입니다.** 대화 컨텍스트가 없으므로 모든 위임은 그 자체로 완결돼야 하고, 취향 판단은 절대 묻지 않습니다 — 수치 계약만.

## 품질 번들

실제로 격차를 닫은 다섯 장치 — 각각 측정된 효과가 있습니다:

1. **계약↔단언 매핑 표** + FAIL-first 증거 — 이것 하나로 자기 저작 테스트 깊이 4배
2. **깊이의 정량화** — "꼼꼼히" 대신 "조항당 단언 2개 이상, 커버리지 표, 발견한 결함은 네 범위 안에서 방어까지"
3. **셀프 리뷰 패스** — "놓쳤을 결함 클래스 3개를 나열하고 각각 단언화하거나 사유 보고"
4. **시각 자기검증** — grok이 자기 캡처를 직접 열어 대조; 체크리스트 1번은 항상 *정체성 가독*("X로 읽히는가? 무엇으로 오독될 수 있는가?")
5. **로직 설계 원칙 4항** — derive-don't-store · 로드 시 재정규화 · 입력 3분류 방어 · 적대적 API 셀프 리뷰

## 정말 되나요?

9라운드에 걸쳐 측정했습니다. 매 라운드 *같은 스펙*을 **grok-4.6**(헤드리스 CLI)과 **Claude Opus 5**에 — 한 라운드는 **Claude Fable 5**에 — 병렬 git 워크트리로 동시에 줬습니다. 과제는 전부 실전 Three.js/WebGPU 프로젝트의 프로덕션 작업: 모듈을 구현하고 *그 검증 게이트까지 스스로 저작*하는 것. 산출물은 **블라인드** 판정 — 무기명 소스, 라운드마다 라벨 스왑, 판정자에게 저자 추정 금지. 요약:

- **기준선: Opus 5에 명백한 패배.** 블라인드 0:5; Opus 5가 단언 24개를 쓸 때 grok은 14개.
- **번들 적용 후: 중요한 곳에서 격차가 닫힘.** grok의 단언 깊이 14 → 42 → 67 → **81**; 마지막 두 라운드에서 시각축이 grok 승으로 반전(한 번은 Opus 5, 한 번은 Fable 5 상대); 속도는 내내 2~4배.
- **끝까지 어려웠던 것:** 설계 무게가 있는 로직 코어(상태 기계·직렬화)는 세 번 시험해 세 번 다 Claude 쪽 승 — 그래서 스킬은 그런 코어를 Claude가 쓰고 grok이 리뷰하라고 말합니다.
- **가장 유용한 발견:** grok의 블라인드 패배는 대부분 **능력 부족이 아니라 기본값의 부재**였고 — 기본값은 스펙에 써넣을 수 있습니다.

## 구성

| 파일 | 역할 |
|---|---|
| `skills/grok-delegate/SKILL.md` | 호출 레시피, git 안전 프로파일, 품질 번들, 병렬 트랙 격리, 리드 검수 체크리스트 |
| `references/spec-preamble.md` | 모든 스펙 앞에 붙는 공통 규칙 — 전부 실제 사고에서 나온 조항 |
| `references/spec-template.md` | 과제별 스펙 골격: 계약·깊이 요구·시각 자기검증 |

안전 기본값: 위임은 열거식 git-deny 프로파일로 돕니다 — grok은 이력·PR을 읽을 수 있지만 커밋·푸시·상태 변경은 못 하고, 그건 리드 몫으로 남습니다. 세 프로파일(strict / 전면 차단 / 워크트리 한정 trusted)은 SKILL.md에 문서화돼 있습니다.

## 로컬 오버레이

프로젝트/개인 전용 컨텍스트(역할표·하우스 게이트 레시피·모델 배정표)는 설치된 스킬 옆 `references/local-overlay.md`에 — 자동으로 함께 적용되고, `install.sh`가 업그레이드에서 보존하며, 이 레포는 배포하지 않습니다.

## 알려진 한계

- 스펙을 쓸 수 없는 탐색적 문제는 위임 대상이 아닙니다 — 리드가 먼저 좁히세요.
- 설계 무게가 있는 로직은 번들 v3로도 완전히 닫히지 않았습니다; Claude가 쓰고 grok이 리뷰하세요.
- 참조 이미지는 과제와 같은 이펙트 유형일 때만 도움이 됩니다.
- grok 보고서는 대체로 정직합니다; 위험은 *없는 것*입니다 — 그래서 리드 검수 체크리스트가 있습니다.
- 지금은 Claude Code 전용입니다. SKILL.md 형식 자체는 이식 가능하지만, 끝까지 실증한 것만 공개합니다.

## 변경 이력

### 2026-08-13 — 진행 가시성, 중간 개입, grok 내장 도구

아래는 전부 실측입니다. 안 되는 것은 안 된다고 적었습니다.

- **라운드 중간 가시성.** `--output-format streaming-json`은 도구 호출 경계를
  표시합니다(CLI 기본값 `plain`은 하지 않습니다). 신설 `scripts/grok-progress.py`가
  그 스트림 **또는** 세션 자신의
  `~/.grok/sessions/<인코딩된-cwd>/<sid>/updates.jsonl`을 도구 호출 한 줄로
  압축합니다(기본 100줄 상한 — 리드가 돌고 있는 라운드를 컨텍스트 폭주 없이
  확인하기 위한 것). `updates.jsonl`은 출력 포맷과 무관하게 기록되므로 과거
  `plain` 실행도 관찰할 수 있습니다.
- **진행 체크포인트**(공용 프리앰블 §9): 위임받은 에이전트가 단계 경계마다
  `PROGRESS <ISO-8601-UTC> <단계> <한 줄>`을 append합니다. 스트림이 없거나
  파싱이 깨질 때의 폴백입니다.
- **중간 개입 — 정직하게.** 두 번째 클라이언트로 **진행 중인 `-p` 턴을 조종할 수
  없습니다**: `grok -r <SID> -p ...`, 공유 `--leader-socket` 조합, ACP
  `session/load` + `session/prompt` 모두 큐잉되고 원래 턴은 끝까지 완주했습니다.
  지원되는 경로는 `kill`(SIGTERM) 후 수정 스펙으로 `-r <SID>` 재개입니다 —
  완료된 도구 결과는 남고, 마지막 완료 도구 이후 작업은 손실되며, 디스크에 이미
  반영된 편집은 되돌려지지 않습니다. `--stream-events`는 존재하지 않고,
  `grok dashboard`는 별개 헤드리스 프로세스를 들여다보는 창으로 검증되지 않았습니다.
- **grok 내장 이미지·비디오 도구.** 헤드리스 세션에서 `image_gen` / `image_edit`가
  동작합니다(`image_to_video` / `reference_to_video`는 가용으로 보고됨). SKILL.md에
  실측 특성을 적었습니다: 산출물이 워크트리 밖 `~/.grok/sessions/...`에 떨어짐,
  JPEG라 알파 없음(투명이 필요하면 키컬러 생성 후 매팅), `1:1`에서 1024px,
  `n`/count 파라미터 없음, 세트 일관성은 캐노니컬 1장 + `image_edit` 파생으로.
- **grok 번들 스킬 인덱스**(`~/.grok/bundled/skills/`): `imagine`, `game-*` 에셋
  계열(`game-tilesets`는 실제 2x2 타일링 검증을 강제), 문서 스킬, `resume-*` 세션
  인터롭, grok 자체 멀티에이전트 루프 — 단 그 루프를 쓰려면 `--no-subagents`를
  빼야 합니다.
